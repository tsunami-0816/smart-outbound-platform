## 补充内容

### 1. 并发控制机制（P1-1 修复）

**租户并发信号量**：
- 每个任务启动时，Redis Lua 脚本原子检查 `concurrency:{tenantId}` 当前值
- 小于租户上限（默认 20，测试基线 50）→ INCR 计数并分配呼叫
- 达到上限 → 号码放入 RabbitMQ 延迟队列，30s 后重试
- 通话结束时 DECR 计数释放名额

```lua
-- Redis Lua 脚本：尝试获取并发名额
local current = redis.call('GET', KEYS[1]) or '0'
if tonumber(current) < tonumber(ARGV[1]) then
    redis.call('INCR', KEYS[1])
    return 1  -- 获取成功
else
    return 0  -- 已满，排队
end
```

### 2. 超时与降级策略（P1-2 修复）

| 外部调用 | 超时 | 重试 | 降级策略 |
|---|---|---|---|
| LLM 对话决策 | 5s | 不重试 | 返回预设话术："抱歉我没听清，请再说一遍" |
| ASR 流式识别 | 2s 无结果 | 重试1次 | 跳过该轮，TTS 说"抱歉信号不好" |
| TTS 合成 | 3s | 重试1次 | 播放静音1s，结束当前通话 |
| 后处理摘要 | 30s | 不重试 | 标记为"摘要生成失败"，人工可重试 |

### 3. Redis 锁完整设计（P1-3 修复）

```lua
-- 防重复拨打锁：SETNX + EXPIRE 原子操作
if redis.call('SET', KEYS[1], ARGV[1], 'NX', 'EX', ARGV[2]) then
    return 1  -- 加锁成功
else
    return 0  -- 已加锁，跳过
end
```
- key: `lock:call:{phone}`，value: taskId
- TTL: 300s（5分钟），防止死锁
- 通话结束后主动 DEL 释放

### 4. 部署端口调整（环境预检修复）

| 服务 | 容器内端口 | 宿主机映射端口 | 说明 |
|---|---|---|---|
| backend | 8080 | **8081** | 避开本机已占用的8080 |
| MySQL | 3306 | **3307** | 避开本机MySQL |
| Redis | 6379 | **6380** | 避开本机Redis |
| ClickHouse HTTP | 8123 | 8123 | 空闲 |
| FreeSWITCH ESL | 8021 | 8021 | 空闲 |

### 5. RabbitMQ 队列设计（P2-1 补充）

| Exchange | Queue | 路由键 | 说明 |
|---|---|---|---|
| call.event | call.dispatch | task.dispatch | 任务调度分发号码 |
| call.event | call.postprocess | call.finish | 通话后处理（摘要/标签） |

### 6. 内存优化建议
- FreeSWITCH 限制最大会话数 30（测试环境）
- ClickHouse 不做持久化，数据存内存+定期落盘
- 启动前用户需 `docker system prune` 清理无用镜像，释放内存
