## 2. 整体分层架构

```
┌─────────────────────────────────────────────────┐
│  接入层  Nginx(可选) / 前端 Vue3+AntV X6         │
│         浏览器 ── HTTPS ──> Spring Boot Gateway  │
├─────────────────────────────────────────────────┤
│  应用层  ┌──────────┐ ┌──────────┐ ┌──────────┐ │
│         │租户管理  │ │流程画布  │ │任务调度  │ │
│         ├──────────┤ ├──────────┤ ├──────────┤ │
│         │通话监控  │ │看板分析  │ │录音管理  │ │
│         └──────────┘ └──────────┘ └──────────┘ │
├─────────────────────────────────────────────────┤
│  服务层  ┌──────────────┐ ┌──────────────┐     │
│         │对话引擎服务   │ │呼叫调度服务  │     │
│         │(ASR→LLM→TTS) │ │(FreeSWITCH) │     │
│         └──────────────┘ └──────────────┘     │
│         ┌──────────────┐ ┌──────────────┐     │
│         │后处理服务    │ │SSE 推送服务  │     │
│         │(摘要/标签)   │ │(实时状态)    │     │
│         └──────────────┘ └──────────────┘     │
├─────────────────────────────────────────────────┤
│  通信层  FreeSWITCH (Docker) + ESL 事件总线     │
│         SIP/RTP 语音流，模拟分机呼叫            │
├─────────────────────────────────────────────────┤
│  外部服务  DeepSeek API / 云 ASR-TTS API       │
├─────────────────────────────────────────────────┤
│  存储层  MySQL(业务) / Redis(缓存/锁) /         │
│         ClickHouse(通话日志) / RabbitMQ(事件)   │
├─────────────────────────────────────────────────┤
│  运维层  Docker Compose + 日志(文件) + 监控指标 │
└─────────────────────────────────────────────────┘
```

### 各层职责
- **接入层**：Vue3 SPA，X6 画布，SSE 连接，RESTful API
- **应用层**：业务 CRUD、租户权限、任务管理
- **服务层**：核心业务逻辑——对话循环、呼叫调度、后处理
- **通信层**：FreeSWITCH 负责实际语音流处理，ESL 推送事件给后端
- **存储层**：MySQL 存业务，Redis 存会话/锁，ClickHouse 存分析
- **运维层**：Docker Compose 编排，日志文件，基础健康检查

## 3. 核心业务链路

### 链路 1：创建对话流程（画布编排）
```
前端拖拽节点 → POST /api/flows → 后端校验 JSON → MySQL flows 表
                                    ↓
                            返回 flowId → 前端绑定画布
```

### 链路 2：批量外呼任务执行
```
创建任务(导入号码) → 写入 MySQL tasks + task_phones
    → RabbitMQ 发送任务消息
    → 呼叫调度消费者拉取号码池
    → ESL 向 FreeSWITCH 发 bgapi 拨打命令
    → FreeSWITCH 接通 → ESL 发 CHANNEL_ANSWER 事件
    → 后端触发对话引擎初始化
```

### 链路 3：实时对话循环（核心）
```
用户说话结束 → ASR 流式返回文本
    → 后端将文本+上下文+流程定义 发给 DeepSeek
    → LLM 决策：提取槽位/走分支/调API/结束
    → 生成回复文本 → 发给 TTS API → 得到音频流
    → ESL 向 FreeSWITCH 播放音频 (uuid_broadcast)
    → 同时 SSE 推送到前端监控页
    → 循环直到流程结束节点
```

### 链路 4：通话后处理
```
FreeSWITCH CHANNEL_HANGUP 事件
    → RabbitMQ 发送通话结束事件
    → 后处理消费者：拉取录音 → 调 ASR 全文转写
    → 调 LLM 生成摘要+意向标签
    → 写入 ClickHouse call_records 表
    → 更新 MySQL tasks 统计
```

### 链路 5：运营看板查询
```
前端请求看板 → 后端聚合查询 ClickHouse
    → 接通率=成功通话/总呼叫
    → 平均通话时长、意向分布
    → 实时监控通过 SSE 订阅当前通话列表
```

## 4. 数据模型设计

### MySQL 核心表

**tenants（租户表）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 租户ID |
| name | VARCHAR(100) | 租户名 |
| concurrency_limit | INT | 并发通话上限 |
| status | TINYINT | 1启用 0禁用 |

**flows（对话流程表）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 流程ID |
| tenant_id | BIGINT | 租户ID |
| name | VARCHAR(200) | 流程名 |
| definition_json | JSON | X6 导出的流程定义 |
| version | INT | 版本号 |
| status | TINYINT | 草稿/已发布 |

**call_tasks（外呼任务表）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 任务ID |
| tenant_id | BIGINT | 租户ID |
| flow_id | BIGINT | 关联流程 |
| name | VARCHAR(200) | 任务名 |
| total_count | INT | 总号码数 |
| success_count | INT | 接通数 |
| status | TINYINT | 待执行/执行中/已完成 |

**task_phones（任务号码表）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | |
| task_id | BIGINT | 任务ID |
| phone | VARCHAR(20) | 号码（模拟用 1001-1050） |
| call_status | TINYINT | 未呼/接通/未接/失败 |

**users（用户表）**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | |
| tenant_id | BIGINT | |
| username | VARCHAR(50) | |
| role | VARCHAR(20) | ADMIN/OPERATOR/VIEWER |

### Redis 键设计
- `session:{callId}` — 当前通话对话状态（槽位/当前节点/上下文）
- `lock:call:{phone}` — 防止重复拨打同一号码（TTL 5min）
- `concurrency:{tenantId}` — 租户当前并发数（INCR/DECR）

### ClickHouse 表

**call_records（通话记录表）**
| 字段 | 类型 | 说明 |
|---|---|---|
| call_id | String | 通话唯一ID |
| tenant_id | UInt64 | 租户ID |
| task_id | UInt64 | 任务ID |
| phone | String | 号码 |
| start_time | DateTime | 开始时间 |
| duration_ms | UInt32 | 通话时长 |
| asr_text | String | 完整转写文本 |
| summary | String | LLM 摘要 |
| intent_tag | String | 意向标签（高/中/低/无意向） |
| recording_url | String | 录音文件路径 |
| cost_tokens | UInt32 | 消耗 Token |

分区：按 `toYYYYMM(start_time)` 月分区

## 5. 接口规范

### 统一响应格式
```json
{ "code": 0, "message": "ok", "data": {} }
```
错误码：0成功 / 401未登录 / 403无权限 / 400参数错误 / 500服务器错误

### 鉴权
JWT Token，Header: `Authorization: Bearer <token>`

### 核心接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/auth/login | 登录 |
| GET/POST/PUT | /api/flows | 流程 CRUD |
| POST | /api/tasks | 创建外呼任务 |
| GET | /api/tasks/{id} | 任务状态 |
| POST | /api/tasks/{id}/start | 启动任务 |
| GET | /api/dashboard/stats | 看板聚合数据 |
| GET | /api/calls/active | 实时进行中通话 |
| GET | /api/calls/stream | SSE 实时通话推送 |
| GET | /api/calls/{callId} | 通话详情 |

## 6. 部署架构

```yaml
docker-compose.yml 服务列表（5个）：
1. freeswitch:1.10.11    # 软交换，暴露 5060/UDP + 8021/ESL
2. mysql:8.0             # 业务库
3. redis:7.2             # 缓存/锁
4. clickhouse:24         # 分析库
5. backend:spring-boot   # Java 后端（含前端静态文件）
```

- 环境：开发环境=Docker Compose 一键启动
- 端口：后端 8080，FreeSWITCH ESL 8021，MySQL 3306，Redis 6379，ClickHouse 8123
- 不做高可用（单机测试项目）
- 前端打包为静态文件由 Spring Boot 直接托管

## 7. 监控与运维

### 监控指标
- 并发通话数（Prometheus /actuator/metrics）
- 对话延迟分布
- ASR/TTS/LLM API 调用成功率
- RabbitMQ 队列积压
- ClickHouse 查询耗时

### 日志
- 应用日志：文件滚动（logs/app.log）
- 通话日志：每次通话完整事件链记录
- 错误日志：单独 error.log

## 8. 技术风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| FreeSWITCH ESL 连接不稳定 | 通话中断 | 重连机制+状态回查 |
| LLM API 延迟波动 | 对话卡顿 | 超时5s+降级话术 |
| ASR/TTS 云 API 不可用 | 无法测试 | 提供 Mock 模式，返回固定文本/音频 |
| 并发 50 路超出 16GB 内存 | OOM | 测试压到 20 路即可，基线 50 路为目标值 |
| SSE 连接数过多 | 内存泄漏 | 连接超时30s+心跳检测 |
